The dyeing plant is no longer asking only for the fastest possible campaign. For this planning run, the operations team wants a shop-floor schedule built in whole time buckets from period 1 through `planning_horizon_T`, with each processing duration taken from table_1.csv and rounded up to the next full time unit before scheduling. Every batch must still follow the same technical route through Vat 1, then Vat 2, then Vat 3, and once a dyeing step begins on a vat it must stay there for its full assigned run length without being split or paused. Because the vats are single-service assets, the dispatchers need a plan in which each batch receives one slot on each vat and no vat is asked to handle overlapping work in the same period.

The handoff convention between vats should match how completion is recorded by production control. If a batch’s booked run on one vat ends in a given indexed period, the next vat may take it at the start of that same indexed period rather than waiting for the following one. That convention matters for preserving the intended timing across the three-stage route. In addition, engineering has locked in a maintenance outage on Vat 2 during periods 4 and 5. The shutdown is a true blackout for that vessel, so any Vat 2 run that would still be occupying the vat in either of those periods is not acceptable. In practical terms, a batch sent to Vat 2 before the service window has to clear the vessel by the end of period 3, while any batch assigned after the work is completed cannot enter before period 6.

Energy policy is the other major change. Finance and sustainability now want the schedule to reflect that each vat incurs a running charge whenever it is in use, at the base rates `energy_cost_v1`, `energy_cost_v2`, and `energy_cost_v3` per active period. The utility’s demand-pricing window covers periods 6, 7, and 8, and activity in those periods is charged at the corresponding vat rate scaled by `peak_energy_multiplier`; all remaining periods are billed at the base rate. The same policy memo also sets an upper allowance `peak_energy_cap` for the total tariff-weighted usage accumulated across those three peak periods, so the plan cannot simply pack too much dyeing activity into that window even if the sequence logic would allow it.

Management therefore wants the recommended schedule to balance campaign completion against electricity spend, rather than optimize either one in isolation. The preferred plan is the one that performs best under the trade-off set by `makespan_weight` and `energy_weight`, using the finishing time of the last batch on Vat 3 as the campaign completion measure and charging energy according to the active periods actually used by each vat, with the peak markup applied in periods 6–8.
